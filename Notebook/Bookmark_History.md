# Profile-owned bookmarks and history

Bookmarks and History use native panels backed by Chromium's profile databases. Command-D adds or edits the current page; Command-Y opens History. Bookmarks support folders, editing, moves, and deletion. Deleting a bookmark folder also deletes its saved descendants; open tabs stay open. Spaces sharing a profile share its bookmarks/history, while separate profiles keep separate libraries. Command-T searches the selected profile's cached bookmarks and loaded history. History initially loads 500 recent unique addresses; Load more expands that scope, and search covers the loaded rows. Removing a history entry deletes all visits to that address in the owning profile. Existing unsupported bookmark addresses remain available for editing/deletion, but only HTTP(S) addresses can be opened here. Library data is not duplicated in the session JSON. Import, sync and all-history clearing are not implemented. Private windows exist separately; these native library panels describe normal Profile browsing only.

Library checks create, edit, move, and delete real Chromium bookmarks, visit and close authored pages, and verify bookmark/history persistence without revisiting those closed pages after restart. The MV3 fixture reads native entries, writes bookmarks, and triggers native library refresh through engine events. Checks cover profile isolation, explicit profile sharing, unknown-profile rejection, foreign bookmark IDs, permanent-root/cycle protection, bounded history queries, URL-specific deletion, and preservation of live tabs/accounts. Unit checks cover malformed responses, stale reads and actions, coalesced events, history loading, and late acknowledgements. Native bookmark light/dark, history, editor, and compact launcher layouts are captured offscreen. Actual native shortcut/menu/dialog input, large-library performance, and private-session behavior remain separate acceptance checks.
