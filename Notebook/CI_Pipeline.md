# CI stages and evidence

The implementation for #334 uses `source-checks.yml` as its orchestration workflow, reusable workflows for build, engine, shipping and CodeQL jobs, and shared setup/evidence composite actions. The preceding design is [[CI_Pipeline_Design]]. Follow-ups add [[Sparkle_Update_Simulation]], [[Commit_Gates]] and the measured parallel graph in [[CI_Run_Time]].

Fast gates use `.venv/bin/python scripts/ci-checks.py`: Swift formatting, license headers, the #336 Notebook-link checker, the shipping `Bundle.module` check, actionlint, shellcheck, action/SwiftPM pins, sensitive-file/size checks, redacted Gitleaks, new-history scanning and all Python tests. `scripts/stage-browser-resources.py` copies every shipping SwiftPM resource bundle into the app, including `ArcusisBrowser_ArcusisBrowser.bundle` for the Audits scripts. The bundle build fails when a produced `ArcusisBrowser_*.bundle` is left unstaged; staging rejects a symlinked Resources output root before replacing bundle contents. Shipping Swift may mention `Bundle.module` only as the development fallback passed to `PackagedResourceBundle.resolve`. A packaged app never evaluates that fallback. Platform-independent gates run on Ubuntu; the complete Python suite remains on macOS for Apple resource compiler coverage. Known docs/site-only diffs run Notebook-link, sensitive-file, Gitleaks and history checks on Ubuntu and skip native jobs. CI and installed hooks share these commands; hooks check exact staged/outgoing content. Missing tools fail. Generated-directory exclusions apply only at repository root; nested source paths remain scanned. Gitleaks has exact-path/exact-value exceptions for the checked-in public extension identity and Sparkle verification keys; other content in those files remains scanned. The installer downloads fixed release assets verified against committed SHA256 digests, refuses symlinked archive-cache entries, and executes no remote shell script. Python dependencies retain the existing hash-pinned requirements. Swift resolution uses the committed lockfile; unit checks also reject lockfile drift.

Swift CodeQL uses a separate stdlib-only Python cache; its helpers do not import release/signing libraries. Native checks and shipping synchronize their Python environment with `uv pip sync --python .venv/bin/python --require-hashes --only-binary=:all: scripts/release-requirements.txt`; the requirements file is a positional input to `sync`. The pinned Periphery ZIP supplies both its executable and `libIndexStore.dylib`; the installer retains that companion beside the executable rather than depending on a Homebrew installation or changing global loader paths.

The Swift extraction checker validates each report tuple's entity and label and reports malformed reports without a traceback before writing coverage output.

The Swift stage starts after selection, parallel with fast/dependency review; the final gate requires all three. It explicitly builds test targets, then runs tests with coverage and per-test xUnit output. Native Swift Testing XML is retained. A stdlib converter produces XCTest JUnit from the same serial test log, validating start/end pairs and outer-suite totals and preserving failures/skips; incomplete logs or missing Swift Testing XML fail. This avoids changing test execution just to obtain reports. The rebased local unit run exposed the need: SwiftPM emitted 503 Swift Testing cases while 119 XCTest cases (17 skipped) appeared only in its console log. Python reports include failures, errors, skips and subtest failures. Other commands produce command-level JUnit and JSON recording exit status, arguments and duration. Stage summaries show results and commit identity; setup logs show Xcode, Swift and Python versions. Regression fixtures isolate `GITHUB_STEP_SUMMARY` so authored failure cases cannot pollute the live stage summary.

Coverage compares the candidate with an immutable event base, built from `git archive` using the same runner/toolchain; recorded toolchain identities must match. Cached coverage profiles are removed from the validated SwiftPM scratch path before each test run. Manual validation compares with the fetched production ref. The gate compares line ratios independently for `BrowserCore`, `ArcusisBrowser`, `ChromiumBridge`, `Shaar` and `ShaarVerification` wherever source coverage exists; core and app coverage must exist. Missing, invalid or duplicate coverage fails. Baseline build/test failure also fails. This does not measure Chromium internals or uninstrumented binary dependencies.

## Selection, caches and required check

PRs, production/native pushes, merge groups, nightly and manual runs use the same graph. The planner normalizes dispatch repetition values to integers from 1 to 10 and emits a numeric JSON value; the caller applies `fromJSON` before passing the typed reusable-workflow input. Invalid counts fail before builds. Known Notebook/root-document/site-only PR diffs skip native work. Empty/unknown diffs select full work; script/workflow changes retain native checks. Swift CodeQL remains selected on every PR regardless of native path selection. Relevant website contracts run through the same required graph, including merge groups. Production and scheduled runs select full work. Manual `deep_checks` defaults true; timing runs may disable the extra sanitizer/dead-code work. Swift analysis remains in its independent security workflow.

Concurrency includes event/ref identity and cancels only superseded PR runs. SwiftPM cache keys include OS/architecture, toolchain, mode, manifest/lockfile and source hashes, with a same-mode/toolchain fallback for incremental builds. Commands always rebuild/test; cached products never count as a passing check. Engine archives use an independent pin key and are checked before extraction/use; failed extraction removes its staging directory. Transferred verification bundles reject a symlinked or missing `build` destination before archive extraction, so restore cannot write outside the checkout. Shipping, verification, coverage and sanitizer scratch paths stay separate.

`CI required` validates that `needs` is a JSON object of stage results and reports malformed input clearly. It runs with `always()` and fails on failure, cancellation, missing prerequisites or unexpected skips. It requires sanitizers/dead-code reporting for nightly/deep manual runs. It is the intended single required status context. Artifacts retain seven days of command logs, JUnit, coverage and authored evidence; Scorecard retains fourteen days. Additional evidence directories use separate artifacts so their common ancestor cannot change the paths consumed by coverage or attestation jobs.

`.github/production-ruleset.json` retains the initial reviewed ruleset snapshot. Live repository ruleset `26350516` is owner-managed and now uses ALLGREEN groups up to five. Existing enterprise PR/signature/no-force-push rules remain authoritative. This change edits neither the ruleset file nor repository rulesets, and does not merge PRs. Merge-group execution and coverage baseline investigation are recorded in [[Test_Coverage]]; configured enforcement and green execution remain separate evidence.

## Update and verification boundaries

Shipping includes [[Sparkle_Update_Simulation]], using ephemeral fixture keys for real installer scenarios. Shared prior-schema upgrade fixtures and seeded randomized tests remain in the unit/Python gates. Local fixture preparation does not prove installation; hosted execution does. Real Developer ID, notarization and Sparkle release signing remain local, with credentials untouched. [[Releasing]] requires green full production Source checks before tagging.

Current before/after measurements, extraction counts, annotation audit and the retained-check matrix live in [[CI_Run_Time]]. The earlier production nightly run [41372340304](https://github.com/arcusis/shaar/actions/runs/41372340304) passed repeated probes, both sanitizers and Periphery; scheduled Scorecard run [41384743935](https://github.com/arcusis/shaar/actions/runs/41384743935) passed. These identify those runs' scope, not proof for a later head. Production-only provenance and a real green merge-group run require their own execution evidence. Signed-distribution provenance stays outside the approved unsigned-CI-candidate scope.

Hook configuration values preserve path whitespace; only Git's output line terminator is removed when reading `core.hooksPath`. The CodeQL extraction checker reports malformed JSON through its intended error path and exit status.
Malformed UTF-8 ownership markers make a logged probe root untrusted, so evidence collection reports the normal foreign-root validation error rather than a decoding traceback.
The shipping-resource source guard matches raw-string delimiters so an embedded quote cannot hide code that follows a raw literal.
