# Chromium 157 shipping QA checklist

Run on the **exact candidate built from the final production commit** with the pinned Chromium 157 archive, then repeat the critical startup/update paths on the Developer ID signed, notarized candidate. On the Office Mac, use hidden/offscreen verification and no focus stealing; this is an authored checklist, not a record of executed tests. Use disposable profiles/sites and note commit, app build, engine version, macOS version, start/end crash-report inventory and evidence path. Do not publish until all release gates in [[Chromium_157_Release_Runbook]] pass. An unavailable external account or device is **unverified**, not passed.

| Area | Exact steps | Expected result |
| --- | --- | --- |
| Cold startup / 157 crash | Launch the shipping bundle with a fresh disposable profile; quit cleanly; relaunch with two saved windows and several tabs; repeat three times. Open `chrome://version` and inspect the app bundle version. | Process stays running, Chromium reports 157, each saved window/tab returns once, no blank host view or new crash report. This specifically gates the startup crash being fixed separately. |
| Normal browsing and tabs | Load an HTTPS page, open three tabs, switch/reorder/close/reopen one, pin one, navigate back/forward and reload. | Correct page remains selected; order, pinned state, history and recovered tab survive without wrong-profile content. |
| Spaces and profiles | Create two disposable profiles and a Space in each; open different local pages, switch profiles/Spaces repeatedly, restart. | Tabs, cookies, Space membership and selected profile remain isolated and restored to their owners. No tab appears under the other profile. |
| Windows and drag | Open two regular windows in one profile; drag an ordinary tab into a chosen position and folder in the other window, then close the source window. Try a pinned tab and a private tab. | Ordinary tab moves once to the chosen position/folder and renders there; no duplicate or lost tab. Pinned/private transfers are refused. |
| Sleeping tabs | In Settings enable sleep, choose 5 minutes, add one site to “Sites that never sleep”; leave an unpinned quiet background tab idle, then select it. Repeat with a pinned tab, audible media, edited form, active download and private tab. | Eligible background tab discards after timeout and reloads on selection; title/URL remain. Exempt tabs stay live, especially a private tab while its profile downloads. No data loss in the edited form. |
| F12 DevTools | On a regular page press F12, close/reopen with F12, then use Option-Command-I; repeat on a private page. Open Elements, Console, Network and Application, plus Shaar Viewports, Network Rules, Copy for agent, Hydration, GraphQL/tRPC, Stacking, Overflow and Focus/contrast where registered. | One Chromium dock opens for the selected tab; shortcut toggles cleanly, correct profile/page data appears, Shaar panels load without a blank panel or retired SwiftUI shell. Closing the tab releases its dock. |
| HTTPS first | On a disposable HTTP-only public-origin fixture, navigate to `http://…` with a new profile; also visit an HTTPS-capable fixture and test an existing profile whose HTTPS-only choice is stored off. | HTTPS-capable page upgrades; public HTTP-only page shows an actionable interstitial rather than a blank page; stored off choice is respected. Do not use `localhost` as the only HTTP check because loopback may be exempt. |
| Website permissions | From a secure fixture page, request camera/mic, geolocation, notifications, MIDI and protocol-handler registration in turn; deny then allow where supported, reload and inspect site settings. Trigger a request from an iframe, switch tabs before answering, and repeat in a private window. | Shaar sheet names the requesting origin and choice; decision reaches the correct frame, stale request cannot grant another tab, stored choice behaves as shown, and private permission lasts only for the visit. macOS privacy denial remains respected. |
| Passkeys and keychain | Inspect the **signed** app's embedded provisioning profile and entitlements; on a supported test site with David's disposable account, register then sign in with iCloud Keychain, restart and retry. Check another profile and a private window separately. | If the approved profile is present, the real system passkey sheet appears and create/get succeed for the correct profile; no unexpected keychain prompt or cross-profile credential. If the profile is absent or Apple entitlement pending, mark this row unverified and omit the passkey note. Ad-hoc success is not proof. |
| Private windows and Quit | Open a private window and a regular window, load a disposable page with a `beforeunload` prompt after a trusted user action, request Quit, cancel once, then confirm; repeat with two private windows and with the regular window already closed. Relaunch. | Cancel keeps both app and page alive; confirm exits without hang; private tabs/history do not restore, normal windows do. No orphan Chromium helper or crash report. |
| Downloads / Library | Download a small known file and a larger file from a local fixture, cancel one, open Library, switch profiles, restart. | Completed file has expected bytes and chosen destination; canceled file is not reported complete; Library entries and profile ownership are correct. |
| Picture in Picture | Play a fixture video, enter PiP, switch tabs/Space and hide the source tab, use PiP controls, then return and close the tab. | Video stays visible in PiP, playback/control state stays in sync, and PiP closes or returns without a stranded window. |
| Keychain regression | With an existing disposable profile credential, restart and load its HTTPS login page; inspect the signed bundle's keychain behavior and repeat in a private window. | Existing credential remains available only in its regular profile; no unexpected macOS keychain alert or private-window credential leak. New save prompts are out of this release. |
| Update and crash audit | Inspect `codesign --verify --deep --strict`, `spctl` for the stapled app/DMG, Sparkle key and bundle feed. Compare `~/Library/Logs/DiagnosticReports/` before/after startup, navigation, DevTools, Quit and update simulation; inspect any `Shaar*` or Chromium helper `.crash`/`.ips`. | Team ID and hardened runtime match all nested code; Gatekeeper accepts notarized app/DMG; Sparkle signature validates against shipped public key; no new app/helper crash. Any new crash is investigated and blocks release. |

Record each row as pass/fail/unverified with evidence. The hidden verification harness and hosted Source checks cover many of these paths, but a fixture result does not by itself prove the signed shipping bundle or real Apple account flow.
