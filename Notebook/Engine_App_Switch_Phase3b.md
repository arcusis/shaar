The bridge also reads Ardia tab `favicon`, `faviconURL`, `themeColor`, `audible`, `muted`, `securityInfo`, `preferredSize`, `popupFeatures`, `navigationEntries`, and `browserId` where their feature owners need them. These are state/event fields or gaps, not interchangeable with a borrowed view pointer. All `ArdiaCore*Delegate` methods are inbound events; replacement must preserve their ownership, ordering, and stale-tab checks before deleting the old implementation.

## Page view contract

1. Window open creates a Shaar-owned `Browser`/`NSWindow` and a retained host `NSView` on the UI thread. A regular window can bind several regular profiles; a private window is fixed to one session. The C ABI returns borrowed host pointers with explicit lifetime until the corresponding confirmed close event. Never expose a pointer after close.
2. Tab open binds one `WebContents` and stable tab ID. `shaar_tab_host_view` returns its native view on the UI thread. Attach moves that view into the Shaar window host after detaching it from any prior superview, sets autoresizing and bounds, and makes only the selected tab visible. Detach removes it before tab close, window close, or cross-window move. Resize on host bounds changes and on fullscreen transitions; focus only the selected visible tab, respecting foreground/background intent.
3. Popup requests carry opener tab, exact regular profile or private session, disposition and gesture. Hold pending WebContents until the app accepts a target window/tab; reject/timeout/opener-close destroys it once. Hidden extension popups use separate hosts and never become the current user window.
4. Fullscreen keeps the same NSWindow/host and resizes the selected view after AppKit transition; no new tab view or borrowed pointer lease is created. PiP is engine-owned, returned via `shaar_media_pip_window`, and cannot be reparented as an ordinary tab. PiP close/restore is driven by media events, with private session IDs preserved.
5. Dispatch attach/detach/selection events after TabStripModel mutation, never reenter placement from an observer callback. A tab strip removal during a move is not a close. Confirm destruction before releasing Swift state. Validate profile/session/window/tab ownership at each C call; reject stale handles and off-main-thread view calls.

## Migration and build requests

| Order | Switch and focused proof | Native builder cost requested in PR description |
| --- | --- | --- |
| 1. This note | Link audit and docs checks. | None. |
| 2. Page hosting | Add window/tab exports, host attach/detach/resize/focus, Swift borrowed view wrapper; native unit tests for selected/background/private/move/close and popup/PiP ownership. | One incremental GN/Ninja compile of Shaar layer targets, then only the hosting unit target and hidden native host probe. The engine-418-own-layer agent owns the build tree. |
| 3. Backend protocol | Select one backend once at startup; Ardia remains the release/default path until source engine parity is proven. Move profiles, then windows/tabs and host views, then navigation. Do not mix handles across backends. | One incremental app/framework link after step 2, then focused hidden profile/window/navigation probes on the resulting source engine. No full engine rebuild request unless the native owner finds an ABI-wide dependency. |
| 4. Remaining modules | Find, downloads/library/site data, extension/DevTools, media/private privacy, storage/release in dependency order. Remove Ardia only after each feature has source-engine runtime evidence. | Request an incremental module compile and its focused probe per module; the final Shaar-only packaging/release pass is a separate gate. |

Swift target builds and mock tests check app typing and adapter behavior; they cannot establish a working Chromium view. Hosted source-engine tests must report the exact engine commit and tested binary. Do not start a local Chromium build in this worktree.
