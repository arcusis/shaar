# Shaar engine module: DevTools and Inspector

Scope: Chromium's built-in Developer Tools frontend, Shaar's Inspector and developer diagnostics, in-process DevTools Protocol access, and Ardia's optional remote-control token. This extends the ABI and migration plan in [[Engine_Shaar_Layer_Design]]; it does not add another ABI, object model, callback channel, or ownership rule. The pinned Ardia sources and Chromium 155 tree were inspected read-only under `/Users/david/orca/workspaces/shaar/engine-333-364/build/EngineSource`.

The source-build overlay staging tool refuses a symlinked `panels/shaar` destination before writing overlay files.

## Current Shaar use

The Swift app imports `ChromiumBridge`, not `ac_engine.h` or `ArdiaCore.h`. There is **no `ac_*` DevTools export resolved by Shaar**. The application currently reaches Ardia through the Objective-C adapter's `ArdiaCoreTab` methods. `ac_devtools_call.mm` is an Ardia implementation file, not a C ABI function used directly by Swift.

## Ardia implementation and patch dependencies

`engine/ardiacore/src/ardia/core/ac_devtools_call.mm` implements `DevToolsCaller` as both `content::DevToolsAgentHostClient` and `WebContentsUserData`. It obtains the tab's host with `DevToolsAgentHost::GetOrCreateFor`, attaches a client, assigns protocol request IDs, dispatches JSON protocol messages and maps replies to callbacks. It rejects protocol errors and times out pending calls. It ignores messages without a request ID, so protocol events are not forwarded. When its pending map empties it posts an idle detach; this is why Shaar currently keeps Inspector/developer leases alive by overlapping 30-second `Runtime.evaluate` promises every 15 seconds (`ChromiumInspector.mm:19-30`, `ChromiumDeveloperMode.mm:22-37`). The Shaar layer should own a real scoped client/subscription lifecycle instead of this keepalive workaround.

`engine/ardiacore/src/ardia/core/ardiacore_api.mm:2050-2088` bridges Objective-C dictionaries to `ardiacore::CallDevTools`; `:2498-2542` calls `DevToolsWindow::OpenDevToolsWindow`, finds/closes the in-tab `WebContents`, returns its native `NSView`, and applies `DevToolsContentsResizingStrategy`. `ac_browser_window.mm:304-314` owns a `DevtoolsUIController`. The Shaar ObjC bridge separately validates tab/profile/window, applies distinct developer and Inspector method allowlists, and rechecks identity after asynchronous replies (`ChromiumDeveloperMode.mm:47-79`, `ChromiumInspector.mm:35-68`). Preserve that scope check in the engine itself; a Swift-side check alone is insufficient.

Docking is coupled to these pinned Chromium patches:

* `chromium-window-docked-devtools.patch` adds the `DevtoolsUIController::UpdateDevtools` seam in `chrome/browser/devtools/devtools_ui_controller.cc`, finds the owning `BrowserWindowInterface`, and reports the inspected and docked DevTools `WebContents` so the external native host can embed it. Implement an equivalent Shaar-owned seam; upstream `DevtoolsUIController` does not notify this app's custom host by itself.
* `chromium-devtools-redock-display.patch` changes `content/app_shim_remote_cocoa/render_widget_host_ns_view_bridge.{h,mm}` and `content/browser/renderer_host/render_widget_host_view_mac.mm` so a detached in-process `NSView` resumes drawing after Chromium re-docks it. Redock and compositor visibility need dedicated coverage if this patch is replaced or dropped.
* `chromium-devtools-window-title.patch` changes `chrome/browser/devtools/devtools_ui_bindings.cc` from “DevTools” to “Developer Tools”. This is user-facing polish, not a protocol or security requirement.
* `chromium-devtools-control-token.patch` changes `content/browser/devtools/devtools_http_handler.{h,cc}`, `content/browser/devtools/devtools_agent_host_impl.cc`, `content/browser/devtools/protocol/input_handler.cc`, and `content/browser/devtools/render_frame_devtools_agent_host.cc`. The hooks authenticate the HTTP/WebSocket path, deny origins and discovery pages, filter commands and events, scope target attachment, gate input, and prevent remote local-file reads/writes.

`engine/chromium/src/chrome/browser/ardia/ac_cli_control.cc` supplies the token service: loopback-only ephemeral socket, random 32-byte Base64URL token, active-target/status reporting, policy checks and a mode-0600 `ArdiaControl.json` control file. The token patch is the enforcement point; the service alone is not a security boundary. This remote-control facility is separate from trusted in-process Inspector calls. The current Swift app does not invoke the CLI service, but issue #418's replacement must explicitly preserve or intentionally disable this capability. Do not retain Ardia hook names or source: reimplement any retained behavior in the Shaar layer and a Shaar-owned Chromium patch.

## ABI additions and Swift adapter

Use the existing ABI v1 rules in [[Engine_Shaar_Layer_Design]] and [[Engine_ABI_Conventions]] exactly: calls use `shaar_submit(shaar_engine *, shaar_scope, shaar_window *, shaar_tab *, shaar_operation, shaar_bytes args_json, shaar_request_id, shaar_reply_fn, void *, shaar_error *)`; cancellation uses `shaar_cancel_request`; all failures use `shaar_error_code`/`shaar_error`; callbacks remain serialized on the Chromium UI thread and async replies are never inline. Add operation IDs and per-operation JSON schemas, not ObjC objects or a second callback channel. Do not pass protocol method names as dynamic strings: dispatch through a fixed C enum and validate params for that command.

The base design's existing operation list ends at `SHAAR_OP_MEDIA_CONTROL` (ordinal 25 if the draft's implicit order is frozen as zero-based). Assign reviewed explicit numeric values before publishing the consolidated header. Append `SHAAR_OP_DEVTOOLS_UI_SHOW = 26`, `SHAAR_OP_DEVTOOLS_UI_CLOSE = 27`, `SHAAR_OP_DEVTOOLS_UI_STATE = 28`, `SHAAR_OP_DEVTOOLS_UI_SET_DOCK = 29`, `SHAAR_OP_DEVTOOLS_CONTROL_ENABLE = 30`, `SHAAR_OP_DEVTOOLS_CONTROL_DISABLE = 31`, and `SHAAR_OP_DEVTOOLS_CONTROL_STATUS = 32`; retain existing `SHAAR_OP_DEVTOOLS_CALL` for protocol commands. These are proposed IDs, not yet published. Each operation requires a profile/session scope and exact tab handle; a window is required for UI operations. `SHAAR_OP_DEVTOOLS_CALL` also carries a fixed `shaar_devtools_command` enum ID in its JSON schema, never an arbitrary method string. The engine checks all handles against the supplied scope and rejects stale targets with `SHAAR_NOT_FOUND`, cross-profile targets with `SHAAR_WRONG_PROFILE`, cross-session targets with `SHAAR_WRONG_SESSION`, private remote control with `SHAAR_PRIVATE_DISALLOWED`, denied policy with `SHAAR_POLICY_BLOCKED`, bad command/params with `SHAAR_INVALID_ARGUMENT`, unavailable protocol/frontend with `SHAAR_NOT_READY`, and Chromium failures with `SHAAR_CHROMIUM_ERROR`. Never encode errors as an empty successful JSON object.

Suggested operation schemas (all include `schemaVersion: 1`; reject unknown security-sensitive keys):

The fixed enums used in those schemas are declared in `shaar_engine.h`: `SHAAR_DEVTOOLS_CAPABILITY_INSPECTOR = 1`, `SHAAR_DEVTOOLS_CAPABILITY_DEVELOPER = 2`; `SHAAR_DEVTOOLS_DOCK_RIGHT = 1`, `_BOTTOM = 2`, `_LEFT = 3`, `_UNDOCKED = 4`; the 43 `shaar_devtools_command` values have the explicit IDs listed below. Every new enum member gets an explicit value in the consolidated header. JSON carries these enum values as bounded integers, never protocol method-name strings.

* UI operations have no action string: `UI_SHOW`, `UI_CLOSE` and `UI_STATE` take `{schemaVersion:1}`; `UI_SET_DOCK` takes `{schemaVersion:1, dockSide:<fixed enum>, extent:<bounded number>}`. `state` returns `open`, enum `dockSide`, and current dock extent. Show/close are idempotent. The returned view remains borrowed per the ABI. Dock changes, frontend open/close, and dock extent updates emit `SHAAR_EVENT_DEVTOOLS` with `{kind:"frontendState", schemaVersion:1, open, dockSide, extent}` after Chromium updates the state.
* `DEVTOOLS_CALL` takes `{schemaVersion:1, capability:<fixed enum>, command:<shaar_devtools_command numeric ID>, params:{...}}`. Define each accepted command with an explicit numeric C enum value and command-specific parameter/result validator. The initial command matrix is: `RUNTIME_EVALUATE=1`, `RUNTIME_RELEASE_OBJECT=2`, `RUNTIME_GET_PROPERTIES=3`, `RUNTIME_RELEASE_OBJECT_GROUP=4`, `DOM_ENABLE=5`, `DOM_GET_DOCUMENT=6`, `DOM_REQUEST_NODE=7`, `DOM_GET_BOX_MODEL=8`, `CSS_ENABLE=9`, `CSS_GET_PLATFORM_FONTS_FOR_NODE=10`, `CSS_GET_BACKGROUND_COLORS=11`, `CSS_GET_MATCHED_STYLES_FOR_NODE=12`, `CSS_GET_COMPUTED_STYLE_FOR_NODE=13`, `CSS_GET_STYLESHEET_TEXT=14`, `PAGE_ENABLE=15`, `PAGE_GET_RESOURCE_TREE=16`, `PAGE_GET_RESOURCE_CONTENT=17`, `PAGE_CAPTURE_SCREENSHOT=18`, `OVERLAY_ENABLE=19`, `OVERLAY_DISABLE=20`, `OVERLAY_SET_SHOW_GRID_OVERLAYS=21`, `OVERLAY_SET_SHOW_FLEX_OVERLAYS=22`, `OVERLAY_GET_GRID_HIGHLIGHT_OBJECTS_FOR_TEST=23`, `DOM_DESCRIBE_NODE=24`, `ACCESSIBILITY_GET_PARTIAL_AX_TREE=25`, `EMULATION_SET_DEVICE_METRICS_OVERRIDE=26`, `EMULATION_CLEAR_DEVICE_METRICS_OVERRIDE=27`, `NETWORK_ENABLE=28`, `NETWORK_EMULATE_NETWORK_CONDITIONS=29`, `EMULATION_SET_CPU_THROTTLING_RATE=30`, `EMULATION_SET_GEOLOCATION_OVERRIDE=31`, `EMULATION_CLEAR_GEOLOCATION_OVERRIDE=32`, `EMULATION_SET_TIMEZONE_OVERRIDE=33`, `EMULATION_SET_LOCALE_OVERRIDE=34`, `EMULATION_SET_USER_AGENT_OVERRIDE=35`, `EMULATION_SET_EMULATED_MEDIA=36`, `PERFORMANCE_ENABLE=37`, `PERFORMANCE_GET_METRICS=38`, `PAGE_ADD_SCRIPT_TO_EVALUATE_ON_NEW_DOCUMENT=39`, `PAGE_REMOVE_SCRIPT_TO_EVALUATE_ON_NEW_DOCUMENT=40`, `NETWORK_GET_COOKIES=41`, `NETWORK_SET_COOKIE=42`, and `NETWORK_DELETE_COOKIES=43`. The capability enum and command matrix jointly enforce the current separate Inspector/developer allowlists; the Network cookie command IDs are reserved for site-data service implementation and are not authorized by either UI capability. This intentionally removes unused cookie protocol access from the developer allowlist; the current Swift developer UI has no call site for them, and cookie clearing already has a separate site-data route. Bind to the passed tab/session on dispatch and reply. Request IDs support timeout, cancellation and stale-result rejection. A response contains only validated command result JSON; protocol exceptions map to typed Chromium errors.
* `DEVTOOLS_CONTROL_ENABLE`, `_DISABLE`, and `_STATUS` replace an action string and take `{schemaVersion:1}`. Enable is bound to the explicitly scoped regular-profile tab. Keep remote control off by default. When enabled, create a short-lived high-entropy bearer token, bind it to that target and engine instance, listen only on loopback, and return the token once in the direct operation result (never in events or logs). Status returns enabled state, loopback port and active connection count but redacts the token. Revoke it on disable, target/profile close, policy change or engine shutdown. A private scope returns `SHAAR_PRIVATE_DISALLOWED`; don't publish private target IDs, URLs or events to a remote client. If a Shaar CLI is the only consumer, keep file/socket mechanics internal to the service and expose no token API to Swift.

Every `SHAAR_EVENT_DEVTOOLS` uses the common event envelope with the regular `profile_id`, first-class `session_id` for OTR, exact `window_id`/`tab_id`, and monotonic sequence. Its payload has `kind` and `schemaVersion`. Never emit protocol messages, inspected page contents, cookies, tokens, raw profile paths or arbitrary error text as events. Add only documented, minimized Inspector notifications after capability checks (for example, a normalized selection revision or resource summary) if the UI needs event-driven updates; keep the current page-injected Inspector state as renderer data, not an unrestricted DevTools event relay. Closing a tab/session emits final state before handles expire.

`ChromiumBridge` should keep the `ARCChromiumRuntime` facade while replacing the Ardia-backed internals. Add adapter methods for frontend state/actions and async capability calls; convert typed `shaar_error` to localized Swift errors immediately; use generated/central Swift request models rather than arbitrary method strings at call sites. `SiteControlTarget` currently has no session ID, so extend the target or introduce an engine request-scope value that carries profile, private-session, window and tab IDs on every call. Replace 150 ms Inspector polling and 500 ms frontend/media polling with scoped events where feasible, preserving polling only for page-injected state that Chromium does not expose. Preserve document-generation cancellation, object-group release, script bootstrap cleanup, private-session isolation, and current docked-view layout/focus rules.

Do not pass the remote bearer token through general SwiftUI observable state. If Swift needs to initiate remote debugging, add a dedicated short-lived secret holder in the bridge, zero/copy-minimize the bytes, redact diagnostics, and release it on revoke; otherwise expose only enable/status/disable and keep credentials inside the CLI service.

## Effort and risks

Estimate: **2–4 engineer-weeks**, aligned with migration row 12 in [[Engine_Shaar_Layer_Design]], plus Chromium sync/build wall time and CI probes. This covers the C++ client/dispatcher and event lifecycle, Swift adapter migration, UI host callback, security tests and focused smoke matrix. The token server can add **1–2 weeks** if Shaar chooses to preserve an app- or CLI-facing remote-control feature; if no supported consumer exists, explicitly keep remote debugging disabled and omit the service operation.

Main risks are Chromium's custom-host docking and macOS compositor/view lifetime (including detach/redock), protocol target/client lifetime across navigation and private-session teardown, overly broad method/parameter allowlists exposing page data or control, and accidentally treating the remote token as equivalent to in-process Inspector authorization. The existing Ardia patch closes security boundaries at multiple protocol layers; a superficial URL-token check is not parity. Chromium upgrades may change DevTools frontend/docking internals and generated protocol schemas. A successful compile or Swift UI test alone does not establish target isolation, private data handling, or remote endpoint security.
