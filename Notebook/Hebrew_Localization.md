# Hebrew localization

BrowserCore and Chromium Bridge catalogs are translation authority for their tables. English remains source language and fallback. Hebrew plural forms use native `one`, `two`, and `other` categories; placeholders stay typed and positional.

Fresh Personal and Work profile/Space labels use launch language when a new session is created. Existing saved names remain user data and are never rewritten after language changes. Shaar remains product brand; `Arcusis Browser` remains application data folder name for compatibility.

Run `.venv/bin/python scripts/check-localization.py` to validate the catalogs directly: every key needs a Hebrew translation with matching typed placeholders and native plural categories, and source references must resolve. No inventory is read or compared. Export a translator inventory with `.venv/bin/python scripts/check-localization.py --write-inventory`; the output is `build/Localization/Hebrew_String_Inventory.csv`, under the ignored build directory. An optional path after `--write-inventory` selects another destination. Generated inventories must not be committed; the old Notebook destination is also ignored to prevent accidental reintroduction. Run offscreen language captures with `python3 scripts/test-localization.py`; runner starts isolated English and Hebrew test children.

The General settings language picker takes effect after restart. System Default follows macOS per-app language preferences. An explicit English or Hebrew choice stores an `AppleLanguages` override in Shaar’s own defaults domain so native frameworks see it at process startup. System Default removes that owned override and restores any previous macOS per-app language preference; global macOS language preferences are unchanged. The restart prompt saves all normal windows and tabs before shutting down Chromium and replacing the process after releasing the workspace lock. That launch bypasses “start fresh” once without changing the saved startup preference. A failed save keeps Shaar open; a cancelled engine quit cancels the pending relaunch. Chromium receives the same launch language and corresponding `Accept-Language` selection. Hebrew dates and byte counts use an explicit Hebrew locale; existing English regional formatting is retained.

The SwiftPM build-tool plugin compiles the Core, Bridge, Shell, Settings, Panels, Inspector, InspectorDetails, and InspectorTools catalogs with Apple's `xcstringstool`. App packaging also compiles localized permission descriptions from `Resources/Localizations/InfoPlist.xcstrings`. Compiled resources live in the BrowserCore package bundle and app `en.lproj` / `he.lproj` directories. The compiler can omit English identity values; English source keys remain valid fallbacks.

See [[Hebrew_Glossary]] for approved terms. The exported inventory contains source locations, catalog keys, translations, and retained-value dispositions. Fast gates generate it once per run and publish it as `hebrew-string-inventory-<run>-<attempt>` in Source checks artifacts, retained for 30 days. Translators can download that artifact without building the app.

Catalog values are authoritative. Inventory source locations are explicitly marked lexical occurrences; they are navigation aids rather than proof that every occurrence binds to that table. Source-reference checks cover direct keys, ternary branches, computed filter titles, native menu titles, and known error helpers, while ignoring commented-out example calls. Brands, user names, URLs, internal service metadata, and diagnostic text have different ownership from interface translations.

## Generated-file audit (#389)

The inventory was the shared generated file rewritten by unrelated UI changes: its lexical source-line references change even when translations do not. Removing the committed copy avoids that cross-branch conflict without changing catalog validation. Other tracked generated files were audited:

- Coverage baselines, JUnit, SBOMs, compiler manifests, and routine visual/engine receipts already live under ignored `build/`; coverage compares an immutable base build rather than a committed report.
- `website/screens/manifest.json` and `Notebook/Assets/*/capture.json` describe specific reviewed screenshot sets. They remain alongside those images as capture evidence; routine UI changes do not regenerate them or require freshness against current sources.
- `Package.resolved`, both `pnpm-lock.yaml` files, and hash-pinned Python requirements are real dependency locks and remain committed.
- `ThirdParty/InspectorFixtures/frameworks.js`, its notices and `pin.json` are a pinned offline test fixture. Its server verifies the bundle hash; rebuilding is explicit and scoped to fixture changes.
- Branding PNG/ICNS exports and the pinned public suffix list are bundled inputs, updated explicitly with their source or upstream pin. Inspector formatter text snapshots are reviewed expected output for specific tests.

No other tracked generated file had the inventory's automatic, repository-wide freshness coupling. No merge driver is needed for the retained files.

Build tests with `swift build --build-tests --jobs 1` before running the capture script. It requires 98 named captures in each language: sidebar and Command-T at two widths, hidden sidebar, mixed Hebrew/Latin queries, every Settings section, all onboarding steps, site control center, mini player, PiP, and the private start page, in light and dark appearances, plus rendered pager, toggle, and language-restart prompt checks. The Inspector includes 26 captures per language: design, CSS, components, accessibility, assets, Notes, and seven page tools, each in light and dark appearances at the production 320-point dock width. The redesigned Inspector adds 16 dock captures per language for Design, Code, Notes and Copy menu at 320/420 points in light/dark, asserting tab and menu bounds in both directions. Eight additional long-content Inspector captures per language verify fixed dock width and readable breadcrumbs across Design/Code switches at both widths. Hidden windows render at fixed 1x scale with animations disabled. Pixel bounds assert Command-T stays within the page card, hidden sidebars clear the page, and pagers/toggles occupy their expected physical positions. Inspector captures seed each selected panel independently so component, accessibility, and asset screens show validated content. Separate geometry tests cover swipe, split, drag exclusions, and favorite ordering. Keyboard glyph groups retain LTR order inside Hebrew descriptions. Private start-page captures also assert that cached SwiftUI content does not retain the private store; localized private HTTP warnings preserve the same weak bindings and explicit consent actions. Captures and assertions do not exercise physical pointer interaction or capture the desktop.

The staged [[CI_Pipeline]] validates catalogs and exports the inventory in fast gates. Ordinary unit runs render the key screens in their resolved launch language so interface paths participate in coverage. The localization stage follows the unit build, runs isolated English/Hebrew captures and the native language fixture, and publishes command logs/JUnit plus authored screenshots and receipts. Both shipping and `CI required` depend on localization success. `CI required` also retains the independent headless Inspector renderer-contract job. Evidence artifacts use `ci-localization-<run>-<attempt>` and `ci-localization-extra-<run>-<attempt>` names. Pure locale-evidence tests reject malformed receipts, mismatched navigator/document language and direction, and internal Chromium UI metadata from the wrong language. Instrumented standalone captures keep LLVM profiles under `build/Verification/localization-profiles` rather than the checkout root.

SwiftUI already mirrors horizontal offsets with layout direction. Sidebar, pager, and toggle offsets stay in logical coordinates. Physical pointer deltas and AppKit frame calculations require explicit conversion.

`python3 scripts/localization-fixture.py` uses marked temporary profiles and loopback HTTP. Ten scenarios cover first launch and restart in each language, English-to-Hebrew and Hebrew-to-English changes on an existing profile, an explicit English choice over a Hebrew macOS per-app preference, and returning to System Default. An isolated app bundle with a unique defaults domain persists choices through the same setter used by the picker; engine launches receive no language-selection arguments. Both profiles are checked. Unit tests cover saving/restoring multiple windows, refusing restart when workspace saves fail, missing and non-executable relaunch paths (including Unicode paths), and persistence through the public language setter without changing the cached launch language. A hidden Settings window captures the pending restart prompt without activation. Verification dispatch tests enforce the isolated fixture bundle identifier and reject missing or unsupported language arguments. Evidence records observed request `Accept-Language`, navigator language, and internal `chrome://version` language/direction. Both test runners restrict child environments. Build or source checks alone do not establish engine runtime acceptance.

Inspector translations stay at native presentation boundaries. Persisted simulation values, DOM selectors, CSS declarations, component names, renderer JSON, and diagnostic archive keys remain data. Copy actions receive original data without adding or stripping bidirectional control characters; code and editing fields use LTR display direction inside Hebrew chrome. Known shipped renderer status/error descriptions are translated without rewriting renderer protocols or unknown page-owned messages.
