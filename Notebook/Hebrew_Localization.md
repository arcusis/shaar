# Hebrew localization

BrowserCore and Chromium Bridge catalogs are translation authority for their tables. English remains source language and fallback. Hebrew plural forms use native `one`, `two`, and `other` categories; placeholders stay typed and positional.

Fresh Personal and Work profile/Space labels use launch language when a new session is created. Existing saved names remain user data and are never rewritten after language changes. Shaar remains product brand; `Arcusis Browser` remains application data folder name for compatibility.

Run `python3 scripts/check-localization.py` to validate catalogs and verify inventory freshness. Regenerate reviewed inventory with `python3 scripts/check-localization.py --write-inventory`. Run offscreen language captures with `python3 scripts/test-localization.py`; runner starts isolated English and Hebrew test children.

The General settings language picker takes effect after restart. System Default follows macOS per-app language preferences. An explicit English or Hebrew choice stores an `AppleLanguages` override in Shaar’s own defaults domain so native frameworks see it at process startup. System Default removes that owned override and restores any previous macOS per-app language preference; global macOS language preferences are unchanged. The restart prompt saves all normal windows and tabs before shutting down Chromium and replacing the process after releasing the workspace lock. That launch bypasses “start fresh” once without changing the saved startup preference. A failed save keeps Shaar open; a cancelled engine quit cancels the pending relaunch. Chromium receives the same launch language and corresponding `Accept-Language` selection. Hebrew dates and byte counts use an explicit Hebrew locale; existing English regional formatting is retained.

The SwiftPM build-tool plugin compiles the Core, Bridge, Shell, Settings, Panels, Inspector, InspectorDetails, and InspectorTools catalogs with Apple's `xcstringstool`. App packaging also compiles localized permission descriptions from `Resources/Localizations/InfoPlist.xcstrings`. Compiled resources live in the BrowserCore package bundle and app `en.lproj` / `he.lproj` directories. The compiler can omit English identity values; English source keys remain valid fallbacks.

See [[Hebrew_Glossary]] for approved terms and [Hebrew_String_Inventory.csv](Hebrew_String_Inventory.csv) for source locations, catalog keys, translations, and retained-value dispositions.

Catalog values are authoritative. Inventory source locations are explicitly marked lexical occurrences; they are navigation aids rather than proof that every occurrence binds to that table. Source-reference checks cover direct keys, ternary branches, computed filter titles, native menu titles, and known error helpers. Brands, user names, URLs, internal service metadata, and diagnostic text have different ownership from interface translations.

Build tests with `swift build --build-tests --jobs 1` before running the capture script. It requires 74 named captures in each language: sidebar and Command-T at two widths, hidden sidebar, mixed Hebrew/Latin queries, every Settings section, all onboarding steps, site control center, mini player, PiP, and the private start page, in light and dark appearances, plus rendered pager, toggle, and language-restart prompt checks. The Inspector includes 26 captures per language: design, CSS, components, accessibility, assets, Notes, and seven page tools, each in light and dark appearances at the production 320-point dock width. Hidden windows render at fixed 1x scale with animations disabled. Pixel bounds assert Command-T stays within the page card, hidden sidebars clear the page, and pagers/toggles occupy their expected physical positions. Inspector captures seed each selected panel independently so component, accessibility, and asset screens show validated content. Separate geometry tests cover swipe, split, drag exclusions, and favorite ordering. Keyboard glyph groups retain LTR order inside Hebrew descriptions. Private start-page captures also assert that cached SwiftUI content does not retain the private store; localized private HTTP warnings preserve the same weak bindings and explicit consent actions. Captures and assertions do not exercise physical pointer interaction or capture the desktop.

The staged [[CI_Pipeline]] validates catalogs and inventory in fast gates. Ordinary unit runs render the key screens in their resolved launch language so interface paths participate in coverage. The localization stage follows the unit build, runs isolated English/Hebrew captures and the native language fixture, and publishes command logs/JUnit plus authored screenshots and receipts. Both shipping and `CI required` depend on localization success. `CI required` also retains the independent headless Inspector renderer-contract job. Evidence artifacts use `ci-localization-<run>-<attempt>` and `ci-localization-extra-<run>-<attempt>` names. Pure locale-evidence tests reject malformed receipts, mismatched navigator/document language and direction, and internal Chromium UI metadata from the wrong language. Instrumented standalone captures keep LLVM profiles under `build/Verification/localization-profiles` rather than the checkout root.

SwiftUI already mirrors horizontal offsets with layout direction. Sidebar, pager, and toggle offsets stay in logical coordinates. Physical pointer deltas and AppKit frame calculations require explicit conversion.

`python3 scripts/localization-fixture.py` uses marked temporary profiles and loopback HTTP. Ten scenarios cover first launch and restart in each language, English-to-Hebrew and Hebrew-to-English changes on an existing profile, an explicit English choice over a Hebrew macOS per-app preference, and returning to System Default. An isolated app bundle with a unique defaults domain persists choices through the same setter used by the picker; engine launches receive no language-selection arguments. Both profiles are checked. Unit tests cover saving/restoring multiple windows and refusing restart when workspace saves fail. Evidence records observed request `Accept-Language`, navigator language, and internal `chrome://version` language/direction. Both test runners restrict child environments. Build or source checks alone do not establish engine runtime acceptance.

Inspector translations stay at native presentation boundaries. Persisted simulation values, DOM selectors, CSS declarations, component names, renderer JSON, and diagnostic archive keys remain data. Copy actions receive original data without adding or stripping bidirectional control characters; code and editing fields use LTR display direction inside Hebrew chrome. Known shipped renderer status/error descriptions are translated without rewriting renderer protocols or unknown page-owned messages.
