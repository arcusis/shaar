# Native keyboard commands

Command-N creates a new engine-backed window sharing Space/profile/pin definitions, with no copied ordinary tabs. Shift-Command-W closes the focused window. Command-T / Command-L opens the launcher. Command-S toggles the sidebar. Command-R reloads the page and Shift-Command-R reloads it bypassing the cache ([[Site_Control_Center]]). Control-Option-[ / ] switches spaces. Arrow keys select launcher results, Return executes, and Escape dismisses. Opening or dismissing the launcher creates no tab. Its opaque adaptive surface stays centered within the page area, including with the sidebar hidden. Rows show existing site icons where available, action labels and Profile context; no support/contact row is added.

Command-Comma opens the reusable native Settings window. When Settings owns focus, Command-W and Shift-Command-W close Settings; page commands remain disabled. Settings profile selection changes only the preference target, never the active browser account.

With an empty query the launcher suggests, in order: Open Tabs (unpinned tabs in this Space), Favorites & Pinned, Recently Closed (this Space) and Most Visited (profile history by visit count, skipping pages already open). Filter chips Tabs, History, Bookmarks and Actions narrow results to one kind; Tab / Shift-Tab cycle through the chips and no filter, and selecting the active chip clears it. Actions are the app's menu commands (New space, Settings, Split View…) with their menu shortcuts, minus the launcher, window-chrome and repeat commands; only commands the launcher's own window can run right now are listed, under their current menu title (Close tab reads Close window when no page is open); choosing one closes the launcher, then runs the command in that window even if another window became key. The UI-only shell has no host, so it lists no Actions. Rows show the site icon, title and grey domain; only the selected row shows its action hint. Up/Down selection spans sections and follows its row by identity, so history or bookmarks loading underneath cannot move Enter onto another row; if the row disappears the selection clamps to the nearest row. Favorites and pinned tabs are capped separately in Favorites & Pinned, and the Tabs chip lists up to 20 open and 20 recently closed tabs.

Opening and closing use a ~180 ms spring scale-and-fade anchored on the panel, the results height animates as rows change, and one selection highlight slides between rows. With Reduce Motion none of these animate. `--render-preview <png> --command [--command-query <text>] [--command-filter tabs|history|bookmarks|actions]` renders the launcher with sample tabs, history, bookmarks and Actions.

A typed query with no chip returns at most ten results, always keeping one slot for Open when input can navigate. Return runs the first row, so the first row is chosen deliberately (issue #351). A typed address (`google.com`, `https://…`, `localhost:3000`) puts Open first, unless a tab, Favorite, bookmark or history entry is already at that exact address; then that row leads and switches to it. Typed text puts Search first, unless a result's site (host without `www.`) or title starts with the text, as `gith` does for an open GitHub tab; then that result leads, up to three matching Actions (word-prefix match) follow the hits, and Open comes last. A URL-substring match alone never leads, so `google.com` no longer opens a `mail.google.com` Favorite. Typed search and the chips share one field-matching and one domain helper. Candidate traversal stops when that prefix is full; selected-Space priority, query matching and profile-scoped bookmark/history behavior remain unchanged. Space sorting and the current Space's ordered-tab array still occur before traversal; this does not establish constant-time search or a measured latency guarantee.
