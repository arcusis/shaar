# Managed workspace and host verification

Managed-workspace checks restore two application clients from one workspace across runner launches. They verify unchanged legacy bytes, stable model ownership and per-window selection/recovery, lazy pin materialization, window-local pin navigation with a shared original address, separate native documents with shared/isolated accounts, catalog propagation without document replacement, folder-collapse independence, and preservation of unrelated live pages. The fixture deliberately retains managed records while closing its hidden native windows for the next launch; it does not exercise production quit/close policy. Unit checks cover migration/round trips, malformed/future/aliased data, account and ID conflicts, shared pin/folder changes, the last-window catalog, reentrant metadata callbacks, failed writes/retry, and retired stores. The production-host fixture below separately covers host integration; these lower-level checks alone do not prove native startup or menu behavior.

Native-host checks use the production host class with hidden windows. Internal fixture setup creates legacy windows; real NSMenu target actions search/find/reopen in the selected owned context, close ordinary/empty windows, and respect modal/foreign-key boundaries. Injected owned key-window identity and notifications make routing deterministic without OS input. The fixture restores saved models/geometry across launches, captures native layouts, and leaves windows open for the runner's actual engine quit. After the engine loop exits, an audit requires quitting closure callbacks and unchanged retained models. A separate parent process verifies that the active OS workspace lock cannot be acquired. Physical key dispatch/focus, native beforeunload/quit cancellation, and actual first/last-engine-window reopen behavior remain separate acceptance checks.

Engine-requested-window checks exercise a user-gesture page popup, origin/source-bound opener `postMessage`, script closure, MV3 normal/popup creation, extension-visible window/tab IDs, background focus retention, rejection of an existing-tab transfer without replacing its document, and a deliberately declined real engine request. A retained extension-created normal window restores in its original account on the next runner launch. The fixture asserts that every in-process native window remains hidden, including any unmanaged window; screenshots remain offscreen native views. These checks cover authored normal-profile requests, not Google authentication, private-session isolation, popup geometry, or every browser type.

For #393, registered Apple-event unit tests cover pre-startup delivery and rollback when native creation fails, without starting Chromium. Menu/catalog tests require no normal New window entry or Command-N binding while retaining private and mini shortcuts and launcher Actions. The hidden host probe closes every managed window, directly invokes the production Dock-reopen Apple-event handler with the old sidebar preference disabled, requires one full hosted main window with sidebar visible, captures it offscreen, and repeats reopen to reject duplicates. Existing initial/restart fixtures retain multiple saved windows. The main menu explicitly rejects exact Command-N before AppKit can fall back to the private-window item; the bridge reserves that chord to suppress Chromium’s built-in New Window action. Unit dispatch checks retain Shift-Command-N and Option-Command-N. These checks do not send physical keys or exercise OS delivery of a Dock click, and the fixture runtime retains its unrelated primary probe window.
