# Managed workspace persistence

The native host uses a managed workspace format and writer. They share Space/profile/folder metadata and original pin definitions, while each window retains distinct tab IDs, current navigation, selection, folder collapse, and closed-tab recovery. New windows copy no ordinary pages; shared pins receive separate local identities and load only when selected in the managed engine clients. Removing a shared pin preserves another window's existing page as an ordinary tab. Shared metadata changes retain existing native documents. This follows Arc's [window-local unpinned/shared-pin model](https://start.arc.net/release-notes), but does not establish complete Arc feature parity. Normal startup holds an OS workspace lock before loading models or profiles. Confirmed ordinary closure removes that window record; engine quit retains open records for restoration. Bounds and focused-window identity persist, and offscreen bounds clamp to current screens. Shared-Space deletion explains its cross-window impact. Real focus/input and cancellation dialogs, and primary/last-engine-window macOS reopen policy remain unverified.

Normal engine-backed sessions live in `~/Library/Application Support/Arcusis Browser/workspace.json`. The version-1 workspace includes a shared catalog, validated per-window schema-v3 snapshots, optional geometry, and focused-window identity. Saved data includes profile/Space/tab IDs, URLs, titles, pins, selection, folder hierarchy/membership/collapse state, and window-local closed-tab recovery. Engine data remains in `Chromium/Profile <profile UUID>` below the same support directory. Real profiles use the OS keychain; the mock keychain is restricted to marked disposable tests. No existing Chrome or Arc profile is imported.

When no workspace exists, `WorkspaceFile` reads legacy `session.json` (v1/v2/v3) without rewriting it or changing identities. Native startup saves the managed snapshot before restoring pages. Existing malformed or unsupported workspace data never falls back to a stale legacy session; both files remain preserved and temporary windows report that changes will not be saved. Valid unsaved state survives IO failure for retry. A mode-0600 `workspace.lock` is held with an exclusive OS lock until engine shutdown, preventing another app process from writing the same workspace; the lock file is retained after release. The UI-only SwiftUI preview uses in-memory sample data and does not modify the workspace or legacy source.
