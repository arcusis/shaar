# Native windows and runtime clients

Native-window checks create a second hidden engine window with shared-profile and separate-profile tabs. They verify distinct real Chromium window IDs, window-owned native views, profile/account retention, rejection of implicit moves and foreign ordering, simultaneous Find tokens/counts, separate extension popups, and extension-visible owning window/profile storage. Clearing or closing one window cannot retire another window's selection or stop normal tab close/recovery recording there. Confirmed closure releases the owning tabs/popup and retires its native window ID; original account documents remain live. These checks use the low-level native API, not a second application store, and do not verify Command-N, per-window menus/persistence, generated-window routing, live focus/input, or close-cancellation dialogs.

Window-client checks exercise two independent application stores and engine clients using the same runtime dispatcher and an explicitly shared profile. They verify page/Find/popup routing, shared bookmark/history/download updates, profile membership filtering, owning-store closed-tab recovery, and continued primary callbacks after secondary closure. Router unit tests reject duplicate/retired clients, cross-window tab/context reassignment and consent resolution, duplicate close delivery, and stale native ownership. The fixture's second store is temporary and does not use a shared session file or prove saved-window coordination/restoration. Both windows remain hidden; native menus, focus/input, and company accounts remain separate acceptance checks.

Activation checks use the authored MV3 service worker's real `chrome.tabs.update` calls, scoped to loopback pages in the requested native window. Worker completion is recorded in profile-local extension storage and observed through the authored content script, independently of the popup that activation may close. Checks cover same-profile Space/folder selection, rapid final-target retention, cross-window routing, inactive-profile protection, saved selection, stale Find/popup disposal, and live account/document retention. Light/dark captures show the selected owning Space after activation. These do not establish physical input/focus, new-window routing, every extension activation path, or activation calls that cause no native selection-change notification.
