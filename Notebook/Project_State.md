# Project scope and acceptance

Native macOS 26+ internal Arc replacement: SwiftUI/AppKit chrome, pinned Chromium, arbitrary Spaces with per-Space pins/folders/saved tabs, simultaneous isolated accounts and explicit profile sharing, page-centered Command-T, Library/downloads and native dragging. Bitwarden is the first optional password-manager integration, controlled in native Settings; supported native backend is under review. Surfshark excluded. Google Workspace/Meet and Cloudflare Access remain company acceptance gates.

Native Settings now has General, Profiles and Shortcuts, unused isolated profile creation, profile renaming, per-Profile launcher search engines and a new-window sidebar preference. Full Settings parity remains [#51](https://github.com/arcusis/browser/issues/51); native password-manager feasibility is [#52](https://github.com/arcusis/browser/issues/52). Further extension-specific integration is paused while that architecture is reviewed.

The [first milestone](https://github.com/arcusis/browser/milestone/1) remains open. GitHub issues own live task state; this note records acceptance boundaries, not session activity.

- Native shell, profile/Space models, launcher, sidebar organization, Library and browser essentials are published on `production`.
- Lazy tab restoration avoids loading every saved page. Sidebar indexing removes repeated sibling scans; model/CPU checks do not establish total-process performance with hundreds of live pages.
- Synthetic extension login/lock/unlock/restart control passes in two separate profiles and an explicitly shared-profile Space. The composed native SDK fixture passes 13 Rust regressions and 30 native stages; this does not link the SDK into the browser or prove full-vault login, autofill/save/update or clean first-click compatibility. Those remain [#52](https://github.com/arcusis/browser/issues/52) and [#9](https://github.com/arcusis/browser/issues/9).
- Original chrome corrections are closed in [#24](https://github.com/arcusis/browser/issues/24), including user confirmation that top-bar dragging works. Broader physical keyboard/pointer/trackpad, drag/drop, native focus and close cancellation remain [#4](https://github.com/arcusis/browser/issues/4), [#5](https://github.com/arcusis/browser/issues/5), [#21](https://github.com/arcusis/browser/issues/21) and [#37](https://github.com/arcusis/browser/issues/37).
- Product private-engine APIs are published in [#131](https://github.com/arcusis/browser/pull/131), with 37 private checks in each initial/restart native phase. Transient private UI ownership and canceled-quit acceptance remain [#124](https://github.com/arcusis/browser/issues/124).
- Real company Workspace/Meet/Cloudflare Access compatibility remains [#1](https://github.com/arcusis/browser/issues/1), [#3](https://github.com/arcusis/browser/issues/3) and [#6](https://github.com/arcusis/browser/issues/6).
- Command-T folder lookup and tab traversal cost is reduced in [#132](https://github.com/arcusis/browser/pull/132); pure search benchmarks do not establish keystroke latency or whole-process performance. Realistic process performance, engine update/provenance and signed/notarized distribution remain [#8](https://github.com/arcusis/browser/issues/8) and [#19](https://github.com/arcusis/browser/issues/19).
- Archive comparison now accepts narrowly validated signing-envelope changes in [#133](https://github.com/arcusis/browser/pull/133): all 547 members of the retained development preview match, including independently verified Mach-O payloads. Source-to-binary attestation remains unverified; matching archive bytes and ad hoc signatures do not close release acceptance. Per-Profile download-directory support still requires a new engine build in [#75](https://github.com/arcusis/browser/issues/75).

Source CI, authored screenshots and hidden native fixtures each prove their own scope. None establishes physical input, company-site compatibility or release acceptance. Company daily use is not accepted yet. Development bundles are ad hoc signed, not notarized releases.
