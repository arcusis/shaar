# Shaar public website

Static HTML generated by TypeScript, a small progressive-enhancement script and original CSS/SVG artwork. Cloudflare Workers serves the built assets. Intended public origin: `https://shaar.arcusis.com`.

## Local development

Use Node.js 22.16+ and pnpm (the exact pnpm version is in `package.json`). No Cloudflare credentials are needed locally.

```sh
cd website
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test
pnpm lint
pnpm build
pnpm check:links
pnpm wrangler dev
```

Wrangler's build hook generates `dist/` before serving at `http://localhost:8787` and rebuilds when source files change. With the server running, `pnpm check:served` checks page responses, assets, headers, clean-URL redirects, real 404s and the appcast boundary. To refresh other copied repository assets, run `pnpm build`.

`pnpm check` combines typecheck, focused tests, lint, build and internal link checks. The link checker verifies local pages, fragments, CSS assets and image descriptions; external URLs are syntax-checked, not requested during PR builds. External links should be checked when their content changes. Font files and licenses are copied from the locked Fontsource packages at build time; the browser makes no external font requests.

## Content and assets

- `src/components/`: shared navigation, layout, home feature stories and landscape.
- `src/pages.ts`: supporting page content. License and notices are embedded verbatim from the repository during builds.
- `src/content.ts`: the published release snapshot, download assets and immutable Sparkle feed URL. Update the snapshot after a release is published; verify filenames and release notes against GitHub Releases. An unreleased app version bump does not update the public download.
- `Branding/shaar-logo.svg` and `.github/assets/`: existing repository artwork and screenshots. Build copies them without changing their visual content.
- The hero landscape is original inline SVG. No reference-site assets or code are used.

Design decisions and accessibility behavior: [Public Website Design](../Notebook/Public_Website_Design.md).

For accessibility checks, open your own local preview tab with `orca tab create --url http://localhost:8787/ --json`, then run `pnpm check:a11y <browserPageId>`. This evaluates the installed axe-core rules in that specific Orca tab through DevTools; it adds no scripts to production assets. Check both themes and viewport sizes, inspect screenshots, and verify keyboard navigation and reduced motion separately. Automated checks do not establish full accessibility conformance. Close your tab afterward.

## CI and deployment

`website-checks.yml` checks PRs and relevant production pushes on Linux, including real local Wrangler serving. It never deploys and has no cloud credentials.

`website-deploy.yml` runs `pnpm wrangler deploy` only on relevant pushes to `production`, after website checks. Before enabling production delivery, an authorized operator must provision a Cloudflare API token scoped to the intended account/Worker as GitHub secret `CLOUDFLARE_API_TOKEN`, and set repository variable `CLOUDFLARE_ACCOUNT_ID`. No token or account identifier is stored in this repository.

Custom-domain binding is deliberately absent from `wrangler.jsonc`. Both `workers_dev` and preview URLs are disabled. After explicit operator approval, configure `shaar.arcusis.com` as a custom domain for Worker `shaar-website` (through Cloudflare or an approved Wrangler route change). Deployment alone does not establish a domain binding or prove public reachability. Never run a production deploy or bind the domain as part of local verification.

This site does **not** publish an appcast. The existing release workflow and Sparkle feed stay at `https://arcusis.github.io/shaar/appcast.xml`. No changes to release publication or installed app update configuration are required.
